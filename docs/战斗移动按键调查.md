# 战斗移动按键调查

看到 `WM_KEYDOWN(VK_PROCESSKEY)`，只能确认输入法已处理这条传统键盘消息。判断战斗移动为何失效，还要知道游戏从哪里读取移动键，以及按下和释放是否都到达游戏的移动逻辑。[ImmGetVirtualKey](https://learn.microsoft.com/en-us/windows/win32/api/imm/nf-imm-immgetvirtualkey) · [Raw Input Overview](https://learn.microsoft.com/en-us/windows/win32/inputdev/about-raw-input)

## Windows 对键盘消息的约定

| 观察位置 | 能确认什么 |
| --- | --- |
| `WM_INPUT` | 应用注册键盘原始输入后可以接收此消息。先确认载荷类型为 `RIM_TYPEKEYBOARD`，因为鼠标也可产生 `WM_INPUT`。键盘载荷的 `MakeCode` 是扫描码，`Flags` 的 `RI_KEY_BREAK` 位用来区分抬起与按下，`VKey` 是对应的传统虚拟键码。[Raw Input Overview](https://learn.microsoft.com/en-us/windows/win32/inputdev/about-raw-input) · [RAWKEYBOARD](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-rawkeyboard) |
| `WM_KEYDOWN` | 非系统键按下时，传统消息发往具有键盘焦点的窗口。`wParam` 是虚拟键码，`lParam` 第 16–23 位是扫描码，第 30 位区分首次按下与自动重复。同一键盘可以同时产生原始输入和传统消息。若为键盘注册 `RIDEV_NOLEGACY`，系统会停止为该应用生成相应的传统键盘消息。[WM_KEYDOWN](https://learn.microsoft.com/en-us/windows/win32/inputdev/wm-keydown) · [RAWINPUTDEVICE](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-rawinputdevice) |
| `WM_KEYDOWN(VK_PROCESSKEY)` | 输入法处理后可把虚拟键标记为 `VK_PROCESSKEY`。要用 `ImmGetVirtualKey` 取回原始虚拟键，必须在应用自己的消息循环取得该消息之后、调用 `TranslateMessage` 之前查询。若消息循环已经翻译消息，窗口过程再查询只会得到 `VK_PROCESSKEY`。[ImmGetVirtualKey](https://learn.microsoft.com/en-us/windows/win32/api/imm/nf-imm-immgetvirtualkey) |

## 暂停 TSF 按键处理能说明什么

`ITfThreadMgr2` 管理调用线程的文本服务。`SuspendKeystrokeHandling()` 暂停按键处理，`ResumeKeystrokeHandling()` 恢复处理。两者均无按键或窗口参数，最低客户端版本为 Windows 8。`S_OK` 只确认调用成功。微软未承诺这些方法会补发已处理的键、恢复游戏窗口焦点、改变 Raw Input 注册或触发游戏的移动动作，因此单凭成功返回值无法判定移动键已经恢复。[ITfThreadMgr2](https://learn.microsoft.com/en-us/windows/win32/api/msctf/nn-msctf-itfthreadmgr2) · [SuspendKeystrokeHandling](https://learn.microsoft.com/en-us/windows/win32/api/msctf/nf-msctf-itfthreadmgr2-suspendkeystrokehandling) · [ResumeKeystrokeHandling](https://learn.microsoft.com/en-us/windows/win32/api/msctf/nf-msctf-itfthreadmgr2-resumekeystrokehandling)

### 窗口通知和文档焦点对照

真实 Windows 测试窗口在旧代码接管文本框时收不到 `IMN_SETOPENSTATUS`。原因为窗口子类把 `WM_IME_NOTIFY` 和 `WM_IME_SETCONTEXT` 交给了 `DefWindowProcW`。本轮改为沿窗口子类链把状态通知、上下文切换和未接管的候选位传给宿主。回归由失败转为通过，覆盖开关、转换模式、合成窗显示位、已接管列表和剩余列表。实车是否在故障时经过此分支仍待检验。[窗口回归](../test_ime_routing.cpp)

在独立窗口保持 `HIMC=0`、进程选用微软拼音的实验中，TSF 编辑会话成功写入「你」。关闭后，无初始焦点和有宿主文档两组都恢复了原文档状态，`TestKeyDown('W')` 都报告未消费。实验中拼音 N/I/空格没有触发真实选词，单独的宿主可编辑文档也能使线程开关从空值变为 1。两项均不足以证明实车故障来自 TSF 文档残留。

本地 1.0.8-beta 验收包 SHA-256 为 `436d12156cda7241d89e7473d71fc17a63ed546c5e1b4c21c9da17e179a579ab`。除物理 W、游戏 W 和位置外，进入战斗及关框后第 1、2、4 秒的回调读取 Flash 两路焦点类型、已有 TSF 文档及输入状态，以及本轮聊天转交给游戏窗口的通知计数。
